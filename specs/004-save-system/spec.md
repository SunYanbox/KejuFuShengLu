# Feature Specification: 存档体系

**Feature Branch**: `004-save-system`

**Created**: 2026-10-11

**Status**: Completed

**Input**: User description: "开始阶段004"

> **阶段定位（2026-10-11，规格书 §16.1 双轨裁决）**：本特性 = **逻辑轨 ④「存档体系
> （MessagePack/JSON/备份）」**（规格书 §16.1 逻辑轨顺序第 4 项、§16.2 对照表 ④ 不变）。
> **界面轨**（新建/读档界面、覆盖确认弹窗、设置面板的「存档格式」项）属 **U1/U5**；
> **成就持久化**（`achievements.json`、来源存档 UUID 归属）属 **逻辑轨 ⑧**。
> 本特性 MUST 只交付可完全脱离界面被验收的存档读写、备份与自动保存能力，
> MUST NOT 实现任何窗口、面板、弹窗或菜单。

## Clarifications

### Session 2026-10-11

- Q: **Q4** 系统凭什么知道「当前档」是哪一份（文件名与格式），从而让每回合的覆盖保存、每 3 回合的备份与退出保存都落在同一份上？(FR-010、FR-012) → A: 由**装配期注入的当前槽位**（档名 + 格式；由回合编排层或存档服务在构造期持有）决定；`GameState` MUST NOT 新增槽位字段、槽位 MUST NOT 随存档落盘；自动保存、备份与退出保存三者共享**同一**槽位。
- Q: **Q5** 玩家把存档改名（或把格式从 `.dat` 换成 `.json`）之后，`backups/` 里那份用旧名字/旧扩展名留下的备份该何去何从？(FR-009、FR-011) → A: **同步处置**——改名时把该存档的备份**一并改名**；格式切换时在新格式主档**写成功之后**移除旧格式备份；任一步失败 MUST NOT 损坏任何一份文件，「每个存档在 `backups/` 下恒 1 份」在操作完成时即成立。
- Q: **Q6** 一次成功结算之后、自动保存写盘失败（磁盘满 / 无写权限 / 目标盘不可用）时，本回合在内存中已经生效的结算结果该如何处置？(FR-010、FR-014、US2 AS5) → A: **保留已推进的内存状态**并把失败以**可识别的方式向上抛出**；MUST NOT 自动回滚（回滚需要结算前快照 = 第二份内存真源）、MUST NOT 静默吞。**「本回合已推进但尚未落盘」是允许的中间态**，下一次保存 MUST 把该回合一并写入。
- Q: **Q7** 判定「同名存档已存在」时是否区分大小写——例如已有 `SongJia.dat` 时请求新建 `songjia`？(FR-008、FR-009) → A: **不区分大小写**（与 Windows 文件系统的实际语义一致，也沿用保留设备名 `CON`/`con` 的既有口径）。存在性查询、覆盖冲突判定与改名目标存在性判定 MUST 用**同一套**不敏感比较；保存时仍**原样保留**玩家输入的大小写写法。
- Q: **Q8** 对**不从前史起点（1 年 1 月）开始**的存档，「每 3 回合」的回合计数按什么基准判定？(FR-011、Edge Cases 的「任意年月」) → A: **游戏进程的当前年月恒从 1 年 1 月起算**（负数/0 年只可能出现在**角色的出生年月**等成员字段，不会出现在推演进程的当前年月里），故回合计数恒为正、无需为负年份设计备份节奏；Edge Cases 的「任意年月」其适用面收窄为**成员年月字段**（读回 MUST NOT 假定它们 ≥ `1 年 1 月`）。

## User Scenarios & Testing *(mandatory)*

001 让家族档案「能表达」，002 让它「会算账」，003 把头（开局）与尾（仕途）补齐——但三者的
成果都只活在内存里：进程一退出，一切归零。本特性把**整份推演状态**落到磁盘（默认二进制
MessagePack `.dat`，可选 JSON `.json`），在**每回合结算后自动覆盖**当前档、**每 3 回合**留一份
备份、退出时再存一次；存档名可改而**存档标识（UUID）不变**；存档目录可配置，默认取可执行
文件旁 `saves/`。交付后，玩家关掉程序、第二天重开，可以从任意一档**逐字段分毫不差**地继续
推演（规格书 §14、§12.3）。

### User Story 1 - 关掉再打开，家族还在原地 (Priority: P1)

玩家推演了十几年：家族里有人中过进士、有人致过仕、有人服过刑、有人已亡故归档，账本上记着
几百条收支，家里还背着一笔贷款。他关掉程序，第二天打开并从最近一档继续——年月、难度、出身、
家族姓氏与「仕」身份、每一位成员（含已亡与外嫁归档者）的档案与功名变迁史、账本全部条目、
现金/储蓄/商本/贷款本金与欠息、田宅铺、米价系数、生活费档位、饥荒阶段、官阶与政绩、待阙与
在职计时、各类状态与计时——每一项都必须与关闭前**逐字段一致**；继续推演也 MUST 得出与
「从未关闭」完全相同的结果。

**Why this priority**: 没有它，001~003 的全部成果在进程退出即归零——「推演可以跨会话」是
沙盒式无限推演的**唯一前提**。它也是本特性其余两个故事的载体：自动保存与备份都必须先有
一份可信的存档形态。

**Independent Test**: 在**临时目录**中构造一份覆盖多种状态（在册 / 已亡 / 外嫁 / 待阙 /
致仕 / 患病 / 饥馑 / 有贷款本息 / 功名变迁史非空 / 非默认难度与非默认出身）的完整状态，
分别以二进制与 JSON 各写入一次再读回，逐字段断言读回值等于写入前的值；再对读回的状态继续
结算若干个月，断言与「同一状态从未落盘」的基线逐字段相同。全程不启动界面、不启动游戏循环。

**Acceptance Scenarios**:

1. **Given** 一份完整推演状态，**When** 以**二进制**格式写入磁盘并从磁盘读回，**Then**
   读回结果的**每一个字段**与写入前相等——含存档标识、当前年月、难度、待生效难度、出身、
   家族姓氏与「仕」身份、家主、全部成员（含归档者）及其全部字段、账本全量条目、资产、
   资金池三池、贷款本金与欠息、米价系数、生活费档位、饥荒阶段与计时（规格书 §14、§12.3）。
2. **Given** 同一份状态，**When** 以 **JSON** 格式写入并读回，**Then** 与 AS1 同样**逐字段
   相等**——两种格式 MUST 承载同一信息集，MUST NOT 出现「某种格式少存一块」的情形（§14）。
3. **Given** 一名处于**待阙 / 致仕 / 服刑 / 患病 / 饥馑**之一的成员、一条**非空功名变迁史**
   与一笔**非零贷款本息**，**When** 存读一轮，**Then** 其状态位、各计时器、官阶、政绩、
   入仕途径与功名记录**逐条**保留，贷款本金与欠息**分别**保留（规格书 §4.1、§5.4、§7.5、§8.2）。
4. **Given** 一份刚读回的存档，**When** 立即再次写入并读回，**Then** 与第一次读回的结果
   **相同**（重复存读不得产生漂移，尤其不得累积或丢失金额精度）。
5. **Given** 一份刚从磁盘读回的存档，**When** 继续结算一个月，**Then** 结果与「同一状态
   从未落盘、直接结算」的基线**逐字段相同**（落盘 MUST NOT 引入任何规则偏移；章程原则 IV）。
6. **Given** 一份包含**已亡 / 外嫁归档成员**的家族，**When** 存读一轮，**Then** 归档成员
   依然在家族中且可按标识取回——归档**不是删除**（规格书 §12.1）。

### User Story 2 - 自动保存与备份：忘记保存的代价是零 (Priority: P2)

玩家不需要记得点「保存」：每推完一个月，当前档就被覆盖写入一次；每满 3 个月，另外留一份
备份；退出时再存一次。哪怕进程被强杀、磁盘写到一半断电，也不会得到一个「半边新、半边旧」
的坏档——要么是上一份好档，要么是这一次的新档。

**Why this priority**: P1 解决了「能不能存」，本故事解决「**什么时候存**」。它把存档从一项
玩家要记住的操作，变成推演本身的收尾动作；没有它，P1 的存档只会在玩家手动触发时才存在。

**Independent Test**: 用可注入的存档服务与固定种子，从同一初始状态连续推进 12 个月，断言
当前档内容等于第 12 个月结束时的状态、备份文件在 3/6/9/12 回合各被写入一次且**始终只有
一份**；再断言一次被**中断的写入**不会损坏原有存档。全程不启动界面。

**Acceptance Scenarios**:

1. **Given** 一次完整成功的月度结算，**When** 结算返回，**Then** 当前存档 MUST 被**覆盖
   写入**一次（规格书 §14）；写入 MUST NOT 发生在结算中途，也 MUST NOT 发生在结算失败的
   调用路径上。
2. **Given** 连续推进的回合数累计到 3 的倍数（3、6、9、12…），**When** 该回合结算完成，
   **Then** MUST 写入一份备份，**覆盖式**、**每个存档只保留最新一份**（规格书 §14）。
3. **Given** 玩家退出程序或返回主菜单，**When** 该流程执行，**Then** MUST 再保存一次当前档
   （规格书 §14）。本特性交付的是**可被该流程调用的同一个保存入口**；进程退出钩子本身属
   **界面轨 U1**（见 Out of Scope）。
4. **Given** 开启了自动保存，**When** 连续推进 N 个月，**Then** 存档内容 MUST 与「关闭自动
   保存、推进 N 个月后手工保存一次」的内容**逐字段相同**——自动保存 MUST NOT 改变推演结果。
5. **Given** 一次**在当前档写入过程中被中断**的自动保存（如进程被杀、目标盘不可写），
   **When** 之后读取该存档，**Then** 读到的 MUST 是**上一份完整存档**，MUST NOT 是半截内容；
   且该存档 MUST 仍可被正常读回（§14 的自动覆盖是本特性中最容易损坏数据的一步）。

### User Story 3 - 档名、目录与格式：存档是玩家的东西 (Priority: P3)

新建存档时玩家起一个名字（中文也行），名字只是文件名；之后想改名就改名，存档的**身份**不变
——成就按身份归属，改名不会把功劳记到别的档上。存档默认落在可执行文件旁的 `saves/`，也可以
配置到别处；默认是二进制（体积小），也可以在设置里选 JSON（可读、可手改、便于排查）。

**Why this priority**: 它是 P1/P2 之上的人机契约：没有它，玩家无法在多个存档之间区分、无法
迁移存档、无法选择格式。但它不改变「存档能否被完整还原」这一核心能力，故排在最后。

**Independent Test**: 在临时目录中逐条断言：中文档名可用、非法档名被拒、同名可查询且未经
确认不覆盖、改名后 UUID 与内容不变、两种格式扩展名正确、自定义根目录生效、缺失与损坏的
存档以可识别的方式失败。全程不需要真实用户界面。

**Acceptance Scenarios**:

1. **Given** 一个中文存档名（如「宋家三十年」），**When** 新建存档，**Then** MUST 成功，
   且磁盘上出现对应扩展名的文件（规格书 §14）。
2. **Given** 一个含 Windows 非法字符的存档名，**When** 新建存档，**Then** MUST 被拒绝或按
   本规格裁决的规范化口径处理，MUST NOT 产生文件系统非法文件名（§14；字符集见 FR-007 的
   裁决）。
3. **Given** 同一目录下已存在同名存档，**When** 请求以同名保存，**Then** 系统 MUST 能回答
   「已存在」，且**未经调用方显式确认** MUST NOT 覆盖（规格书 §14）——弹窗本身属**界面轨 U1**。
4. **Given** 一份已存在的存档，**When** 玩家把它改名，**Then** 存档标识（UUID）与游戏内容
   MUST **完全不变**，只有文件名与显示名改变（规格书 §14；001 FR-012 的「改档名不变性」在
   本特性首次获得可验证对象），且该存档在 `backups/` 下的备份 MUST **随之同名**、
   MUST NOT 留下旧名副本（**2026-10-11 裁决 Q5**）。
5. **Given** 未指定格式，**When** 新建存档，**Then** MUST 使用**二进制**、扩展名 `.dat`；
   **Given** 选择 JSON，**Then** 扩展名 MUST 为 `.json`（规格书 §14）。
6. **Given** 配置了一个自定义存档根目录，**When** 保存与读取，**Then** 文件 MUST 落在该目录
   下；**Given** 未配置，**Then** MUST 取可执行文件相对路径 `saves/`（规格书 §14；章程
   「存档、日志等运行时路径 MUST 可配置」）。
7. **Given** 一个不存在的档名、一个内容被截断的存档文件、一个结构可解析但字段缺失的文件，
   **When** 尝试读取，**Then** 三种情形 MUST 各自以**可识别的方式失败**，MUST NOT 返回一个
   「看起来能玩」的默认状态或部分状态（否则玩家会以为读档成功而丢掉了真实进度）。

### Edge Cases

- **写入被中断（进程被杀 / 磁盘满 / 无写权限）**（规格书 §14）：磁盘上 MUST 是**上一份完整
  存档**；MUST NOT 出现半截文件覆盖掉好档。读取被中断后剩下的那份档 MUST 正常成功。
- **存档名是空串、纯空白、或超长**（规格书 §14）：MUST 被拒绝，MUST NOT 落到文件系统再报错。
- **存档名是 Windows 保留设备名**（`CON`、`PRN`、`AUX`、`NUL`、`COM1`~`COM9`、`LPT1`~`LPT9`）
  或**以点号/空白结尾**（规格书 §14 未列举）：MUST 被拒绝或规范化，MUST NOT 依赖文件系统的
  静默行为（见 Assumptions）。
- **存档目录不存在**（规格书 §14）：MUST 自动创建；**创建失败或无写权限**时 MUST 以可识别
  的方式失败，MUST NOT 静默吞掉（否则玩家以为存上了）。
- **仅大小写不同的两个档名**（如 `SongJia.dat` 与 `songjia`，**2026-10-11 裁决 Q7**）：
  MUST 视为**同名**——在 Windows 上它们本就是同一个文件；MUST NOT 出现「系统回答不存在、
  随后的保存静默覆盖另一个写法」的情形，未经显式确认 MUST 拒绝覆盖（FR-008）。
- **读取一个由更新版本写出的存档**（§14 未规定版本字段）：MUST 给出**明确拒绝**，MUST NOT
  静默误读成一份「字段缺失但看起来正常」的存档（见 FR-015 与 Assumptions）。
- **同一存档同时存在两种格式的文件**（先以 `.dat` 保存、之后把格式设置改为 JSON）：MUST NOT
  出现「同一存档标识在同一目录下有两个候选文件」的歧义状态——主档目录与 `backups/` **同样适用**
  （处置口径见 Assumptions 与裁决 Q5）。
- **两个不同档名但相同 UUID 的存档并存**（001 R-03 已登记的理论风险）：MUST 被阻止——
  存档标识是 §14 成就归属的键，重复会让成绩记到别的档上（见 Assumptions）。
- **100 年推演的账本体量**（001 R-16 登记的待实测项，预计数万条）：无论是否分块/压缩，读回
  后的账本条目 MUST **全量且顺序一致**，MUST NOT 因体量原因被截断或丢弃（见 FR-021 的裁决）。
- **金额精度**（002 契约四 §4 不变量 1）：存档 MUST 按金额的**原值**持久化，MUST NOT 统一
  舍入到固定小数位——002 登记的 1 ulp 容差是 `decimal` 表示精度所致的既有取舍，本特性
  MUST NOT 借「统一舍入口径」改变它（见 Assumptions）。
- **任意年月（含前史纪年）**（规格书 §3 的 §17 裁决回写；**2026-10-11 裁决 Q8** 界定适用面）：
  **成员的年月字段**（出生年月、功名变迁史年月等）MUST 支持任意年份（含 `0` 与负数）与
  1~12 月，读回实现 MUST NOT 假定它们一定 ≥ `1 年 1 月`；而**存档的当前年月**在真实推演中
  恒从 `1 年 1 月` 起算——负数年份不会出现在推演进程的当前年月里，故 FR-011 的回合计数
  恒为正、无需为负年份另设备份节奏。
- **备份文件缺失或损坏**（规格书 §14）：MUST NOT 影响当前档的读写；仅在需要备份的能力上
  降级，且该降级 MUST 以可识别的方式暴露。
- **自动保存写盘失败**（磁盘满 / 无写权限 / 目标盘被拔，见 FR-010）：本回合的内存状态 MUST
  保留（「已推进但未落盘」是允许的中间态），失败 MUST 以可识别的方式暴露；MUST NOT 回滚、
  MUST NOT 静默吞。下一次保存 MUST 把该回合一并写入，MUST NOT 因上次失败而跳过或错位。
- **目标盘暂时不可写、稍后恢复**：恢复后的第一次保存 MUST 写入**当前**完整状态（而不是只写入
  失败那一回合的旧快照），账本条目 MUST 全量且顺序一致。
- **家族姓氏与存档名不一致**（规格书 §12.4、§14）：改名 MUST NOT 改动家族姓氏，改家族姓氏
  MUST NOT 改动存档名——两者是独立概念。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供「把当前整份推演状态写入存档」与「从存档还原整份推演状态」两项
  能力，且该能力 MUST 位于**可脱离界面被单元测试**的非 UI 层（章程原则 II、原则 IV；
  规格书 §2 已把 `ISaveService` 列为 `KFL.Infrastructure` 的跨层接口）。
- **FR-002**: 存档 MUST 覆盖**全部**推演状态：存档标识、当前年月、难度与待生效难度、出身、
  家族（姓氏、「仕」身份、家主、**全部成员含归档者**）、成员的全部字段（姓名 / 性别 /
  出生年月 / 辈分 / 四项天赋 / 学业 / 体质 / 天命寿数 / **功名变迁史全量** / 官阶 / 政绩 /
  状态位 / 各状态计时 / 职业 / 父母引用 / 配偶与前任配偶引用）、资金池（现金 / 储蓄 / 商本）、
  **账本全量条目**、资产（田 / 宅 / 铺）、贷款**本金与欠息**、米价系数、生活费档位与待生效
  档位、饥荒阶段与计时（规格书 §4.1、§5.4、§12.1、§12.3、§14）。
- **FR-003**: 读回的状态 MUST 与写入前**逐字段相等**；MUST NOT 有任何字段被丢弃、默认化或
  近似化。金额 MUST 按原值持久化（`decimal` 精度不得被统一量化，见 Edge Cases）。
- **FR-004**: 系统 MUST 支持两种存档格式——**二进制 = MessagePack（扩展名 `.dat`）**与
  **JSON = System.Text.Json（扩展名 `.json`）**——且两者 MUST 承载**同一信息集**（规格书 §14）。
- **FR-005**: 未指定格式时 MUST 取**二进制**（规格书 §14）；格式选择 MUST 只影响存储形态，
  MUST NOT 影响任何游戏语义——同一状态以两种格式存读 MUST 得到等价结果。
- **FR-006**: 存档根目录 MUST 可配置；未配置时 MUST 取**可执行文件相对路径 `saves/`**
  （规格书 §14；章程「运行时路径 MUST 可配置」）。备份的落点见 FR-011 的裁决。
- **FR-007**（**2026-10-11 裁决 Q3**）: 存档名 MUST 接受中文，并 MUST 过滤 Windows **实际
  非法字符集 `\ / : * ? " < > |`**（9 个）；`-`（连字符）MUST 放行，MUST NOT 被当成非法字符。
  规格书 §14 原文列举的 `-` 认定为 `*` 的笔误，已按 §17 裁决回写该节（见 Assumptions）。
- **FR-008**: 系统 MUST 能回答「同名存档是否已存在」，并 MUST 提供**显式覆盖开关**；未经
  显式确认时 MUST 拒绝覆盖（规格书 §14）。弹窗与确认交互属**界面轨 U1**，不在本特性。
  **同名判定 MUST 大小写不敏感**（**2026-10-11 裁决 Q7**）：`SongJia` 与 `songjia` 视为同名，
  覆盖未经显式确认 MUST 被拒绝；存在性查询、覆盖冲突与改名目标判定 MUST 用同一套比较口径。
- **FR-009**: 改档名 MUST 只改变文件名与显示名，MUST NOT 改变存档标识（UUID）、MUST NOT
  改变游戏内容、MUST NOT 改变家族姓氏（规格书 §14、§12.4；001 FR-012）。该存档在
  `backups/` 下的备份 MUST **随主档一并改名**（**2026-10-11 裁决 Q5**），使「主档名 =
  备份名」的口径在改名后仍成立；备份改名失败 MUST NOT 损坏主档，且 MUST 以可识别的方式暴露。
- **FR-010**: 每一回合（= 1 游戏月）结算**完整成功**后，系统 MUST **覆盖写入当前存档**
  （规格书 §14、§3）。写入 MUST NOT 发生在结算中途；结算抛出异常时 MUST NOT 覆盖当前档。
  「当前存档」由**装配期注入的当前槽位**（档名 + 格式）确定；该槽位 MUST NOT 成为 `GameState`
  的字段、MUST NOT 随存档落盘（**2026-10-11 裁决 Q4**，见 Clarifications）。
  **写盘失败**（磁盘满 / 无写权限 / 目标盘不可用）时 MUST **保留已推进的内存状态**并把失败以
  可识别的方式传出去，MUST NOT 回滚本回合、MUST NOT 静默吞；「本回合已推进但未落盘」是允许的
  中间态，下一次保存 MUST 把该回合一并写入（**2026-10-11 裁决 Q6**，见 Edge Cases）。
- **FR-011**（**2026-10-11 裁决 Q1**）: 回合计数每累计到 **3 的倍数**时，系统 MUST 在**该回合
  自动保存完成之后**把刚写入的内容**复制**一份为备份：落点 = **可配置存档根目录下的
  `backups/`**（默认即 `saves/backups/`），文件名 = `存档名` + **与当前存档相同的扩展名**；
  **覆盖式**、每个存档只保留最新一份（规格书 §14，按 §17 裁决回写）。存档格式切换时，
  新格式主档**写成功之后** MUST 一并移除旧格式的备份（**2026-10-11 裁决 Q5**），使
  「每个存档在 `backups/` 下恒 1 份」不被格式切换破坏。
  回合计数由**当前年月相对纪元 `1 年 1 月`** 派生；真实推演中它恒为正，故「3 的倍数」在
  实战中不存在负数区间的歧义（**2026-10-11 裁决 Q8**）。
- **FR-012**: 退出程序（或返回主菜单）时 MUST 保存一次当前档，且 MUST 复用与 FR-010
  **相同的保存入口**与**同一个当前槽位**（规格书 §14）。本特性交付该入口；进程退出钩子属**界面轨 U1**
  （章程原则 VI：不得另写一套绕过规则的实现）。
- **FR-013**: 写入 MUST 具备**原子性**：任何中断 MUST NOT 在目标路径留下半截存档、也
  MUST NOT 损坏原有存档（Edge Cases；规格书 §14 的「覆盖写入」是本特性最易损数据的一步）。
- **FR-014**: 读档失败（文件缺失 / 内容损坏 / 结构不符）MUST 以**可识别的方式**失败，
  MUST NOT 返回默认状态或部分状态，MUST NOT 修改原文件，且 MUST NOT 让内存中的当前状态被
  半成品污染（Edge Cases、US3 AS7）。
- **FR-015**: 系统 MUST NOT **静默误读**一份它无法完整还原的存档（例如由更新版本写出、
  缺少本版本必需的字段）：发现无法完整还原时 MUST 明确失败（Edge Cases）。
- **FR-016**: 金额 MUST 以**原值**持久化，MUST NOT 施加统一的舍入/量化口径——002 登记的
  1 ulp 容差属既有取舍，本特性 MUST NOT 借「统一舍入口径」改变 002 的账本等式口径
  （002 契约四 §4 不变量 1；章程原则 IV）。
- **FR-017**: 落盘 MUST NOT 改变推演结果：读回后继续推演的行为 MUST 与「同一状态从未落盘」
  一致；同一状态反复存读 MUST NOT 产生漂移（US1 AS4、AS5；章程原则 IV）。
- **FR-018**: 存档实现 MUST NOT 直接读取系统时钟（墙钟）；自动保存与备份的**时点 MUST 完全
  由回合数与显式入参决定**（章程原则 II；001 契约一 §2.1 的 G-07 禁用 token 清单）。
- **FR-019**: 文件系统访问 MUST 收敛在存档实现的**少数明确行**上，并逐行使用行级豁免注释
  `// arch-guard:allow` **在同一行说明理由**（001 `contracts/architecture-guard.md` §2.1）；
  `KFL.Core` 与 `KFL.Rules` 中的禁用 token 违规数 MUST 为 **0**（章程原则 II）。
- **FR-020**: 落盘 MUST NOT 以**放宽既有不变量**为代价：MUST NOT 为序列化给 `KFL.Core` 的
  不可变字段新增公开写入通道，MUST NOT 引入与既有存档级状态 / 家族 / 经济聚合**并存的第二份
  内存真源**，MUST NOT 让 `KFL.Core` 依赖具体序列化框架（章程原则 II；001 data-model §2.1
  不变量 2；003 的「单一真源」口径）。
- **FR-021**（**2026-10-11 裁决 Q2**）: 账本 MUST **全量**随存档持久化——这是规格书 §14
  「所有月份的统计信息会全部写入存档文件」的实现口径（§12.3 的 §17 裁决回写：统计一律由
  账本聚合得出）；系统 MUST NOT **另存**冗余的每月汇总值。落盘组织取**单一存档文件、全量、
  不分块、不压缩**：100 年（1200 回合）的存档 MUST 在该形态下完整可写、可读（001 R-16 与
  002 research 登记的「账本落盘体量与是否按年分块」这一待决项**至此结清**）。
- **FR-022**: 本特性 MUST 交付针对以下各点的单元测试，且测试 MUST 使用**临时目录**、
  MUST NOT 污染仓库工作区：两种格式各一轮覆盖全部字段类别的存读等价（US1）、自动保存与
  备份的回合节奏与中断安全（US2）、命名与非法字符、同名未确认不覆盖、改名后的标识不变性、
  路径可配置、缺失与损坏文件的失败形态（US3）（章程原则 IV、原则 V 的门禁）。
- **FR-023**: 仓库 MUST 忽略运行时存档产物（`saves/` 及其备份目录），使门禁与提交不因本机
  存档而变脏（章程「开发工作流与质量门禁」：提交前工作区洁净）。
- **FR-024**: 为交付二进制格式而新增的依赖 MUST 支持 `net10.0` 并在本规格或计划文档中
  **说明必要性**（章程「技术栈与工程约束」；规格书 §1 已把 MessagePack-CSharp 列为
  二进制存档的指定依赖）。

### Key Entities

- **存档文件（SaveFile）**：一份完整推演状态的落盘形态，由「存档目录 + 存档名 + 格式扩展名」
  定位。它是**存储侧**的载体，MUST NOT 成为与内存状态并存的第二份真源（FR-020）。
- **存档标识（Save Identity，UUID）**：新建存档时生成一次，改档名不变（规格书 §14）。
  它是成就归属（逻辑轨 ⑧）与「同一存档只有一个当前档」两条口径的键。
- **当前档槽位（Current Save Slot）**：**运行时会话**信息 = 档名 + 格式，由装配期注入
  （回合编排层或存档服务的构造参数持有）；自动保存、备份与退出保存三者共享它
  （FR-010、FR-012；**2026-10-11 裁决 Q4**）。它是**会话**状态，MUST NOT 进入 `GameState`、
  MUST NOT 随存档落盘——落盘里已有 `GameState.Id`（存档标识）承担「这份档是谁」。
- **存档名（Save Name）**：文件名的显示侧，支持中文，受非法字符与保留名约束；与**家族姓氏**
  （§12.4）无耦合——改名不改姓氏，改姓氏不改档名。
- **存档目录（Save Root）**：可配置；默认取可执行文件相对路径 `saves/`；备份的落点见 FR-011。
- **存档格式（Save Format）**：二进制（`.dat`，**默认**）/ JSON（`.json`），只影响存储形态、
  不影响游戏语义（规格书 §14）。
- **自动保存与备份节奏（Save Cadence）**：每回合结算后覆盖当前档；每 3 回合一份覆盖式备份；
  退出时再存一次。它是「回合数 → 该不该写、写哪一份」的规则，MUST 可脱离界面被断言。
- **存档服务接缝（ISaveService）**：规格书 §2 列在 `KFL.Infrastructure` 的跨层接口；001 已
  声明「各自阶段带着真实需求回来定义」，本特性**首次定义并实现**它（章程原则 II）。

## Out of Scope

- **成就**：`achievements.json`、按难度记录完成状态与最早完成日期、按来源存档 UUID 归属、
  成就解锁判定与提示（规格书 §14、§14.1；**逻辑轨 ⑧**）。本特性只保证**存档标识**被如实地
  持久化并被改名保护，使 ⑧ 的 UUID 归属有可靠的键。
- **界面**：新建/读档/回主菜单界面、存档列表、**同名覆盖确认弹窗**、设置面板中的「存档格式」
  「存档目录」「难度」「姓氏」项（规格书 §11、§14；**界面轨 U1/U5**）。本特性只交付被它们
  调用的能力（存在性查询、显式覆盖开关、格式与目录入参）。
- **进程退出钩子与主界面事件**：本特性交付**保存入口**，MUST NOT 实现 WPF 生命周期钩子
  （§14 的「退出游戏时自动保存」在 U1 接线；FR-012）。
- **调试控制台**（规格书 §13；**界面轨 U4**）——本特性 MUST NOT 为控制台预置绕过规则的入口
  （章程原则 VI）。
- **统计页、图表与 CSV 导出**（规格书 §12.3；**界面轨 U3**）：本特性只保证账本全量入档。
- **绝嗣结局画面与家族编年史**（规格书 §15；**逻辑轨 ⑧**）。
- **跨 .NET 版本的随机重放**：本特性持久化的是**状态**而非「种子 + 操作序列」，故 001 登记的
  「`System.Random` 算法不保证跨 .NET 版本稳定」对本特性**不构成约束**（001
  implementation-notes 第 3 条、003 research 同款取舍）——见 Assumptions。
- **存档格式的迁移与向下兼容**：本特性 MUST 拒绝无法完整还原的存档，MUST NOT 实现旧格式到
  新格式的迁移（规格书 §14 未定义任何迁移规则；章程「复杂度 MUST 被论证」）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一份覆盖全部字段类别的夹具，在**两种格式**下各自的存读等价断言**差异项数 = 0**；
  断言须逐类覆盖至少：存档标识 / 年月 / 难度与待生效难度 / 出身 / 家族（姓氏、仕身份、家主、
  成员数含归档）/ 成员全部字段 / 功名变迁史 / 账本 / 三池金额 / 资产 / 贷款本金与欠息 /
  米价系数 / 生活费档位与待生效档位 / 饥荒阶段与计时（共 ≥14 类）。
- **SC-002**: 连续落盘 24 个月后再读回，账本条目数与逐条内容、资金池三池与全部成员档案
  与写入前**完全一致**；读回后继续推进 12 个月的结果与「从未落盘」基线**逐字段差异 = 0**。
- **SC-003**: 推进 12 个回合后，当前档被覆盖写入 **12 次**、备份被写入 **4 次**（第 3、6、9、
  12 回合各一次），且目录中该存档的备份文件恒为 **1 个**（覆盖式，覆盖率为 100%）；
  **改名与格式切换之后该不变式 MUST 仍成立**（备份随主档改名、旧格式备份被移除；
  **2026-10-11 裁决 Q5**）。
- **SC-004**: 改名前后对比，存档标识与游戏内容**差异 = 0**；家族姓氏亦**未被改动**。
- **SC-005**: 空 / 纯空白 / 超长 / 含非法字符 / 保留设备名 / **仅大小写不同**的存档名，
  逐条断言**拒绝率 100%**（或按裁决的规范化口径 100% 落到合法名），且文件系统上 MUST NOT
  出现非法文件名；仅大小写不同的名字 MUST 被判定为同名、未经确认 MUST NOT 覆盖
  （**2026-10-11 裁决 Q7**）。
- **SC-006**: 注入一次「写入中途失败」，结果 MUST 满足：目标路径上存在的文件**要么**是写入
  前的完整存档、**要么**是写入后的完整存档，且**始终可被成功读回**（「两边都不是」的情形
  出现 0 次）。
- **SC-007**: 缺失 / 截断 / 结构不符 / 版本不符四类输入，MUST **各自**产生可识别的失败信号
  （而非默认状态），且失败后原文件内容与内存状态**均未被修改**（差异 = 0）。
- **SC-008**: `KFL.Core` 与 `KFL.Rules` 中的 G-07 禁用 token 违规数 = **0**；存档实现中
  每一处文件系统访问都在**同一行**带 `// arch-guard:allow` 与理由，豁免行数可被逐一列举。
- **SC-009**: 一次完整门禁（`dotnet build` + `dotnet test`）跑完后，仓库工作区的存档相关
  变更数为 **0**（测试全部落在临时目录；FR-022、FR-023）。
- **SC-010**: 100 年（1200 回合）的存档 MUST 能被完整写入并读回，账本条目**丢失数 = 0**，
  且落盘形态为**单一存档文件**（不分块、不压缩）——即 FR-021 的裁决在极端体量下仍成立。

## 增补（2026-10-19，玩家反馈第四轮：开局菜单读档入口）

> 依据：文末「裁决块：2026-10-19（玩家反馈第四轮）」Q5。玩家反馈：在**开局菜单**里点

   即守卫的语义是「无会话 ⇒ 只允许菜单级动作」，MUST NOT 是「无会话 ⇒ 一律返回」。
3. **失败可见**：菜单里没有选中项时，MUST 在概览区给出「没有可读取的存档。」，
   MUST NOT 静默无反应。
