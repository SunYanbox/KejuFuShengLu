  「对方阶层按**家族声望**/资产加权随机」，但规格书**全文没有事件表**（§13.2 的「事件下拉 + 触发」是
  调试控制台 U4）：随机提亲的触发者/时机/概率、榜下捉婿的概率与「谁付聘礼、金额归谁」、阶层抽样权重
  全部缺失；且「**声望**」在规格书全文**没有定义**（§9.1 是唯一出现处，人物与家族都无此属性）。

  系数**（简单 2.5% / 普通 5% / 困难 6.5% / 地狱 7%），命中后在被提亲候选集合内均匀抽 1 名；
  **榜下捉婿**为新科一甲成员在及第**次月**由富商提亲、由**对方支付** 500~1000 贯给本家族、
  基准概率 **30% × 负面事件系数**，MUST NOT 叠加 §9.2 的基础聘礼/嫁妆；
  **阶层加权只按家族总资产分档**（MUST NOT 新增「声望」属性），三档权重与阈值见 FR-014。
  落地：FR-014、FR-019、FR-020；落地值 MUST 单点声明于配置并封印于契约。
- Q: **Q2** 规格书 §3:43 把「**疾病治疗抉择**」列为会暂停快进的**决策类事件**，§4.3:93 只写
  「病程 2~4 月；药费 0.05~0.5 贯/月 × 难度支出系数」，**未写**药费是否需玩家抉择、不治疗的后果，
  且固定 −10 体质/月 与固定 2~4 月病程会让「小病 + 饥馑」在半年内累积致死
  → A: **改为「以体质为自愈概率 + 可选疗程」的机制**（**取代** §4.3 的「病程 2~4 月」与固定
  「−10 体质/月」）：患病时 roll 一个**疾病程度** `s ∈ [0, 1]`（均匀），`s` 同时决定该次疾病的
  **每月体质扣减 = 2 + 8s**（即 2~10）与**每月药费 = 0.05 + 0.45s 贯**（× 支出系数）；
  每月结算**先扣体质、再掷清除**，**不治疗**时清除概率 = `体质 × 0.75 / 100`
  （100 体质 ⇒ 75%/月；10 体质 ⇒ 7.5%/月）；玩家可发起一次**疗程**（默认持续**一个季度 = 3 个月**），
  疗程内按月支付药费且清除概率 = `体质 × 0.75 / 100 × 1.10 + 0.20`（**可 > 1 ⇒ 必愈**）；
  疗程结束后仍未愈可再开新疗程；体质归零即病亡。未治疗的疾病 MUST NOT 自行过期。
  落地：FR-029、FR-030。**其中「患病概率随年龄分档」一段已被 Q4 裁决整体替换**（Q4 改按体质计算），
  **「自愈概率」段的 `0.75` 与疗程公式已被 Q6 裁决替换**（改为 `1.00` 与天赋放大形式），
  「疾病程度 `s` / 药费 / 疗程 3 个月 / 未治疗不过期」三段继续有效。
- Q: **Q4**（2026-10-17 用户二次裁决，替换 Q2 的患病概率段）规格书 `科举浮生录规格书.md:93` 原文
  「患病概率：16 岁以上 2.5%/月，40 岁以上 5%，体质<50 再 ×2，封顶 20%；病程 2~4 月；
  药费 0.05~0.5 贯/月 × 难度支出系数」——用户指出：**病程不按月预先指定，而是每月按概率判定能否痊愈**；
  **患病概率不按年龄（寿命）而按体质**：`体质 100 ⇒ 0.25%`、`体质 1 ⇒ 40%`；并给出四项天赋的乘数。
  → A: **按体质线性插值的患病概率 + 天赋乘数**：
  `p_患病(体质 c) = 0.25 + (40 − 0.25) × (100 − c) / 99`（百分数，`c` 取当月初值；
  MUST 单点声明两个锚点 `0.25 / 40`），**年龄档、体质<50 的 ×2 与 20% 封顶一律删除**；
  `q_痊愈(c) = 0.75 × c / 100`（百分数，取**当月扣减后**的体质）；疗程期 `q = min(1, q × 1.10 + 0.20)`。
  **注：本行的 `0.75` 与疗程式已被 Q6 取代**（`1.00` 与 `min(1, (体质 × 1.10/100 + 0.20) × m_q + b)`）。
  天赋乘数（**乘算**，`m_p` 作用于患病概率、`m_q` 作用于痊愈概率）：
  **农 `0.80 / 1.20`；仕 `0.95 / 1.10`；工 `1.10 / 1.10`；商 `1.05 / 0.95`**。
  取用口径见 Assumptions（**取该成员最高的那项天赋**，并列按 农→商→仕→工 顺序；待用户复述确认）。
  **数值平衡分析（本特性要求）结论**：存在一条**存活阈值** `体质 c*`（此处月净变化 = 0：
  以 `s̄ = 0.5` 计，患病月 −6、健康月 +1 ⇒ `−6π + (1 − π) = 0` ⇒ `π = 1/7` ⇒ `6·m_p·p = m_q·q`）：
  **农 68.6 / 仕 74.0 / 工（及无乘数）76.7 / 商 78.5**；开启疗程后同一顺序为
  **58.2 / 65.2 / 68.8 / 71.1**。`c > c*` ⇒ 体质单调回升至 100（疾病只是暂时的）；
  `c < c*` ⇒ 进入**缓慢死亡螺旋**（均值场下从 70 起步：农不出事、仕 59 月、工 46 月、商 40 月病亡；
  从 60 起步：43 / 31 / 27 / 25 月）。**风险点**：新生 / 娶入 / 买来者的体质均为 `N(85, 10)`，
  故 **约 20.3% 的新成员出生即落在 `c* = 76.7` 之下**（`P(c < 78.5) = 25.8%`、`P(c < 68.6) = 5.1%`），
  这些成员（非农天赋且不接受疗程时）会被判为「最终病亡」；把痊愈斜率从 `0.75` 提到 `1.00 / 1.25 / 1.50`
  可把阈值压到 `71.1 / 66.3 / 62.0`（落险比例 8.2% / 3.0% / 1.1%）。**是否调参须由用户裁决**
  （**已于 Q6 裁决：取 `1.00`**，并附「宽限月」与「疗程公式的乘数位置」两项）。
  落地：FR-029、FR-030、FR-001、SC-014。

  `P = Σ w(L)` 为唯一自变量，`w(L) = 0.02 + 1.48 × (18 − L) / 17`（官阶 `L ∈ [1, 18]`：`L18` 最低 ⇒ +2%、
  `L1` 最高 ⇒ +150%，线性）；**金额 = `Next(500, 1001) × (1 + P)` 贯**（仍由对方支付、MUST NOT 乘支出系数）；
  **触发概率 = `30% × 负面事件系数 ÷ (1 + P)`**；**配偶自带功名按 `P` 分档**：`P < 1` ⇒ 白身、
  `1 ≤ P < 3` ⇒ 举人、`P ≥ 3` ⇒ 贡士（**MUST NOT 进士**，§9.2「一般不高于贡士」）；事件 MUST 产出
  **待应答提议**并携带该配偶的**全部数值**（姓名、性别、年龄、四项天赋、学业、体质、寿数、功名、阶层、

  出生即注定」**只对 `≥ 24` 岁、非农天赋且不接受疗程的成员成立**（详见 SC-015 的分带金色值）。
  **注**：本段的 `53.3` 与 `67.2` 按当时的 qBase `0.75` 计算；**Q6 上调为 `1.00` 后**，钳制起点变为
  `体质 ≥ 40`、`12~24` 岁段阈值变为 **62.3**、`3~12` 岁段仍 **59.1**，一律以 SC-015 为准。
  落地：FR-001、FR-019、FR-020、FR-029、FR-030、FR-044、FR-049、SC-013~SC-015。

本特性补齐这条代谢链：新增**固定第 ⑧ 步「人口与健康推进步」**（原 ⑧ 科举季 → ⑨、⑨ 推进时间 → ⑩，
合计**十步**），并交付婚姻、生育、疾病、寿命、家主继任与买人口的完整规则。

### User Story 1 - 婚配：托媒、娶入与嫁出 (Priority: P1)

玩家在 005 的科举季与 006 的贿赂之外，第一次能让家族**长出新的一支**：为一名已达婚龄的在册成员
**主动托媒**，付 5 贯 × 支出系数掷 50% 的成功判定；成功后由对方阶层加权随机产生一名婚配对象，
按 §9.2 的金额表完成**聘礼 / 嫁妆**的双向转移并落账本，对象按「无父母参照者」口径初始化后
经 `Family.Marry` 入册、辈分落定。玩家也可反向**嫁出**本家成员：付本家阶层嫁妆、收对方阶层聘礼，
该成员随即**外嫁归档**（冻结、不计口、数据保留）。若被托媒者是「仕」成员且身为现任官员，还可叠加
**买功名婚姻**：额外支付自己年俸的 150%，配偶进门自带低一级功名。

**Why this priority**: 婚配是家族延续的唯一入口（§9.4 的生育以「已婚夫妇」为前提），也是解锁
§4.4 辈分落定、『仕』族规格（§10.2）与 ⑧ 的「秦晋之好 / 榜下捉婿」等成就的唯一途径。
它完全由**玩家动作**驱动，不依赖新增结算步，可以独立交付并被独立演示：只做本故事，
家族就已经能娶进、嫁出，`RegisteredMembers` 与族谱随之变化。

**Independent Test**: 在只有 001~006 的基线上实现本故事的规则入口与查询面，不插入任何结算步：
为一名成年未婚男成员托媒至成功 → 断言现金按「5 贯 × 支出系数」减少、`Ledger` 新增一条
`MatchmakerFee`、对象属性落在「无父母参照者」分布口径内、`SpouseId` 双向一致、聘礼/嫁妆按对方
阶层与支出系数逐格吻合、辈分等于家族内配偶辈分；再对一名女性成员执行嫁出 → 断言
`StatusFlag.MarriedOut` 置位、从 `RegisteredMembers` 与 `CountedMembers.Counted` 中消失、
`ArchivedMembers` 仍可 `TryGet`。

**Acceptance Scenarios**:

   **When** 对其发起一次托媒且成功判定通过，**Then** 扣款恰为 5 贯 × 支出系数、新增恰好 1 条
   `MatchmakerFee` 资金类条目、产生 1 名对象（年龄与其相差 ≤ 5 岁、未婚）、其天赋/学业/体质
   落在 §4.2「无父母参照者」口径、`Lifespan` 已 roll（只 clamp 下界 0）、并落 1 条 `MarriageFormed` 事件类条目。

### User Story 2 - 生育与遗传：次月分娩 (Priority: P2)

玩家为一对已婚夫妇发起一次**生育决策**（女方 16~45 岁），支付 10 贯 × 支出系数；该申请登记后，
**次月**的人口与健康推进步执行**分娩**：掷 5% 的分娩死亡判定（简单 2.5% / 地狱 7%）、产生一名
新生儿，其性别 50/50、姓随家族姓氏、名经注入的姓名来源，天赋/学业/体质按 §4.2 的遗传公式
（`N(父母均值, σ)`、`σ = |父 − 母| / 2 + 5`、clamp 0~100、体质下限 20）从父母推导，
辈分 = 父母辈分 + 1，`Lifespan` 照常 roll；此后**出生当月、满 1 岁生日月、满 2 岁生日月**各掷一次
夭折判定（10% / 简单 5% / 地狱 12%），满 3 岁后不再判定。

**Why this priority**: 生育是「家族不死」的正反馈来源，也是 ⑧ 的「三代同堂 / 五世其昌 / 人丁兴旺 /
百子千孙 / 红颜薄命 / 襁褓之殇」全部计数的来源；遗传公式是规格书 §16 点名的**必测项**之一
（当前全仓无任何遗传测试）。它依赖 US3 引入的推进步，但**只**依赖该步的分娩子步。

**Independent Test**: 只实现生育申请 + 推进步的「分娩与新生儿」子步（其余子步留空），
用固定种子断言：申请当月扣 10 贯 × 支出系数并落条目、次月诞生 1 名成员、其父母引用双向、
`Generation` = 父辈分 + 1、四项天赋各自落在 `N((父+母)/2, |父−母|/2+5)` 的 clamps 区间内、
体质不低于 20、学业按 `N(父母均值 × 0.5, σ)` 且与天赋取自同一 σ、姓名取自 `INameGenerator`。

**Acceptance Scenarios**:

1. **Given** 一对在册已婚夫妇、女方 30 岁、本年度尚未申请过生育、现金 + 储蓄充足，
   **When** 发起生育申请，**Then** 扣 10 贯 × 支出系数、新增 1 条 `ChildbirthExpense` 条目、
   登记一条待分娩记录，且**当月不产生**新生儿。
2. **Given** 存在待分娩记录，**When** 执行次月结算的人口与健康推进步，**Then** 家族新增 1 名成员，
   性别服从 50/50 且与名称来源的 `NextGivenName(gender)` 一致，`FatherId`/`MotherId` 同指该夫妇，
   辈分 = 父母辈分 + 1，且在 `RegisteredMembers` 中可见。
3. **Given** 父母天赋 `(80, 60)`，**When** 新生儿天赋被 roll，**Then** 其 σ 恰为 `|80−60|/2+5 = 15`
   且取值 clamp 到 0~100；同样的父/母值在体质上产生 σ 相同、下限为 20。
4. **Given** 分娩死亡判定命中（种子可构造），**When** 该月结算完成，**Then** 母亲置
   `StatusFlag.Deceased`、进 `ArchivedMembers`、当月事实段含死因「分娩」，
   且新生儿**照常出生**（规格书未规定婴儿随母死亡）。
5. **Given** 同一对夫妇在本年度已申请过一次生育，**When** 再次申请，**Then** 拒绝、
   随机消费 0、状态与现金不变；跨年（次年 1 月后）可再次申请。
6. **Given** 女方 15 岁或 46 岁，或该成员已婚但配偶已亡故（`SpouseId == null`），
   **When** 查询生育可行性，**Then** 返回不可用且不消耗随机。

### User Story 3 - 成长、疾病与天命寿数 (Priority: P3)

每个成员在月末结算里第一次开始**变老、变强或变弱、生病、死去**：指派读书者学业 +1.5/月
（延名师 5 贯/月 → +2.25/月，士出身藏书 +10%），16 岁以上未读书者学业 −0.5/月；
生活费付清且非饥馑非患病者体质 +1/月；患病概率不再按年龄分档，而是**按体质**：体质 100 → 0.25%/月、
体质 1 → 40%/月线性插值，再乘该项**主导天赋**的乘数（农 0.8 / 仕 0.95 / 工 1.1 / 商 1.05）；
**三岁前不得病**（该年龄段已有夭折机制）；**儿童与青年的痊愈概率另有三段年龄增益**：
3~12 岁 **+0.60**、12~24 岁 **+0.30**、24 岁以上无；
患病时 roll 一个**疾病程度**，由它决定每月体质扣减（**2~10**）与每月药费（**0.05~0.50 贯**），
**新确诊当月是「宽限月」**（不扣体质、不付药费、不掷清除，次月起才进入循环）；
**每月按概率判定能否痊愈**（100 体质 ⇒ 100%/月，10 体质 ⇒ 10%/月，同样乘天赋系数并叠加年龄增益），
玩家也可花钱开一个**疗程**（默认一个季度）把清除概率抬到
**`min(1, (体质 × 1.10/100 + 0.20) × m_q + b)`**；
体质降到 0 即病亡；饥馑严重期每人每月 −10 体质并按 5% 掷死亡判定；
到达天命寿数当月自然死亡（服刑 / 患病 / 外嫁均不豁免）。所有死亡在当月**死亡结算**中置 `Deceased`、
进族谱归档、落事件类条目，死因在当月事实段可读。

**Why this priority**: 它是 006 明写移交的能力（`specs/006-bribery-punishment/spec.md:461-463`：
「服刑期间的『天命寿数照常生效』由 ⑦ 的死亡判定实现」）、002 明写移交的能力
（`contracts/monthly-settlement.md:222` 的饥馑体质与 5% 死亡判定），也是 ⑧ 的「寿比南山 /
路有冻死骨」与绝嗣判定的唯一数据来源；没有它，家主继任与买人口都没有场景。

**Independent Test**: 只实现推进步的患病 / 成长 / 饥馑体质 / 寿终 / 夭折 / 死亡结算子步
（不实现婚育与买人口），用固定种子构造：一名体质 100 的患病成员在 100%/月 的清除概率下
**宽限月结束后的第一个月即愈**（且确诊当月 0 扣减、0 药费）；一名体质 20、疾病程度接近 1 的
患病成员在体质归零时病亡；
一名 `Lifespan = 45` 的 45 岁成员在生日当月自然死亡；一名处于饥馑严重期的成员每月体质 −10
且 5% 判定可复现；所有死亡都置 `Deceased`、离开 `RegisteredMembers`、落进 `ArchivedMembers`。

**Acceptance Scenarios**:

1. **Given** 一名 20 岁、`Occupation.Studying` 的在册成员，**When** 执行一次月末结算，
   **Then** 其学业 +1.5（士出身 ×1.1）、无其他写入；同月再断言体质 +1 且上限 100 不越界。
2. **Given** 一名体质 45 的成员（其主导天赋为农），**When** 患病判定被构造命中，**Then** 其患病概率
   恰为 `[0.25 + 39.75 × 55 / 99] × 0.80 = 17.86%`、`StatusFlag.Ill` 置位、`StatusTimers` 出现疾病程度 `s`
   与疗程剩余月数（不治疗时疗程为 0）、**确诊当月既不扣体质也不产生 `MedicineExpense`**（宽限月）；
   **When** 进入次月，**Then** 先按 `2 + 8s` 扣体质、再按「扣减后体质 × 1.00/100 × 1.20」掷清除；
   **Given** 玩家发起一次疗程，**Then** 连续 3 个月每月扣一条 `MedicineExpense`
   （`(0.05 + 0.45s) × 支出系数`）且清除概率变为 `min(1, (体质 × 1.10/100 + 0.20) × 1.20)`
   （计算值 ≥ 1 时该月必愈且不消耗随机）；清除命中后 `Ill` 解除、不再扣体质与药费。
2b. **Given** 四名体质 100 的成员分别主导 农 / 仕 / 工 / 商 天赋，**When** 各自掷一次患病判定，
   **Then** 概率分别为 `0.25 × 0.80 = 0.20%`、`0.238%`、`0.275%`、`0.263%`；体质 1 时分别为
   `40 × 0.80 = 32%`、`38%`、`44%`、`42%`（**不再有 20% 封顶**）；**三岁以上一律适用，两岁及以下免病**。
2c. **Given** 三名体质 70、主导天赋均为商（`m_q = 0.95`）的**已患病成员**（上月经确诊，本次是宽限月
   之后的第一个月；构造 `s = 0.5` ⇒ 先扣 6 体质至 64），年龄分别为 2 / 10 / 20 岁，**Then**：
   2 岁成员 **MUST NOT 进入患病判定**（该月患病相关随机消费恰为 0 次）；
   10 岁成员的清除概率为 `min(1, 0.64 × 1.00 × 0.95 + 0.60) = 1.0`（**钳到 1 ⇒ 当月必愈、不消费随机**）；
   20 岁成员为 `0.608 + 0.30 = 0.908`（掷一次判定）；
   若把 20 岁成员改为 24 岁，则概率降为 **`0.608`（年龄增益归零）**，**Then** 再次验证
   「`min(1, …)` 短路不产生随机消费」这一确定性要求。
3. **Given** 一名患病成员的体质降到 0，**When** 该月结算完成，**Then** 其置 `Deceased`、
   当月事实段死因为「病亡」、进 `ArchivedMembers`、新增 1 条 `MemberDeceased` 事件类条目，
   且**同月不发生**绝嗣判定（§15 属 ⑧）。
4. **Given** 一名 `Lifespan = 45` 的 45 岁成员（服刑中、患病中或被外嫁归档三种构造），
   **When** 其生日当月结算完成，**Then** 一律死亡（§4.1「服刑/患病/外嫁不豁免」），
   死因为「寿终」；外嫁者的死亡 MUST NOT 使其回到在册集合。
5. **Given** 家族处于饥馑严重期（`FamilyEconomy.Famine.Stage`，002 已交付阶段机），
   **When** 执行结算，**Then** 每人每月 −10 体质、每人每月 5% 死亡判定照常执行；
   **Given** 处于救济模式（12 个月），**Then** 体质 MUST NOT 下降（§5.4 字面口径）；
   本特性 MUST NOT 改写 002 的阶段迁移与时限。
6. **Given** 一名 6 岁儿童未指派读书，**When** 执行结算，**Then** 其学业 MUST NOT 因未读书而下降
   （§4.3「儿童不遗忘」）；**Given** 一名 17 岁成员未指派读书，**Then** 学业 −0.5。

### User Story 4 - 家主继任 (Priority: P4)

家主亡故（或从在册集合中消失）的**同月**，推进步在死亡结算之后立即按 §4.4 的直系优先顺序产生新家主：
① 在册男性子女中年龄最大 → ② 已亡儿子的在册男性后代（代际就近优先、同代年龄最大） → ③ 亲兄弟 →
④ 在册男性中年龄最大且子代最多者；候选范围为在册男性（含服刑、待阙）；若家族中**没有**在册男性，
则 `HeadId` 置 `null`（家主空缺），且**不构成绝嗣**。

**Why this priority**: US3 一旦开始死人，`HeadId` 就可能指向已归档成员，违反 001 `data-model.md`
的不变量 6 与 `tests/KFL.Tests/Infrastructure/SaveStateValidatorTests.cs:68-73` 的存档校验；
§4.4 的继任规则所需数据 001 已全部提供（`specs/001-core-skeleton/data-model.md:318-322`），
本故事只补判定逻辑。

**Independent Test**: 只实现推进步的「家主继任」子步并用夹具直接构造死亡：`FamilyFixtures.MultiGeneration()`
的三代家庭中让现任家主死亡 → 断言新家主恰为「在册男性子女中年龄最大」者；
逐一构造四档候选场景断言选择与 §4.4 完全一致；清空全部在册男性后断言 `HeadId == null`
且**不**触发绝嗣。

**Acceptance Scenarios**:

1. **Given** 家主有 3 名在册男性子女（年龄 20 / 25 / 30）与 1 名排行更大的侄子，
   **When** 家主死亡，**Then** 新家主为 30 岁的儿子（直系优先于旁系）。
2. **Given** 家主已无在世在册男子，但一名已亡儿子留有 2 名在册男性后代，
   **When** 家主死亡，**Then** 新家主取「代际就近优先、同代年龄最大」的那一名。
3. **Given** 家主无子、父母已亡，但有一名在册亲兄弟，**When** 家主死亡，
   **Then** 新家主为该亲兄弟而不是「年龄更大的远房堂叔」。
4. **Given** 家族只剩下一名在册男性（服刑中）与两名外嫁女性，**When** 家主死亡，
   **Then** 新家主为该服刑成员（候选含服刑/待阙）。
5. **Given** 全族无在册男性，**When** 家主死亡，**Then** `HeadId` 为 `null`、
   存档校验仍通过、MUST NOT 产生绝嗣判定或结局。
6. **Given** 家主死亡的当月，**When** 该月结算完成，**Then** `HeadId` 已指向在册成员
   （MUST NOT 出现「结算结束但 `HeadId` 悬空」的中间态）。

### User Story 5 - 买人口（补充旁系成员） (Priority: P5)

玩家在任意月份现金购买旁系成员：本年第 n 名价格 10n 贯（每年 1 月重置），
支付现金 → 储蓄，付不起即无法购买且不转贷款；买来者年龄 8~16 均匀随机、性别 50/50、
家族内无父母、属性按「无父母参照者」口径、冠家族姓，辈分 = 家主辈分 + 1，计入在册存活与统计。

**Why this priority**: 它是玩家在婚育之外的第二条扩员途径，并直接支撑 ⑧ 的「人丁兴旺」家族计数；
不设购买门槛、不可指定性别年龄，因而实现面窄（一次扣款 + 一次成员初始化），
但依赖 US4 的辈分基准（`Family.BoughtCollateralGeneration` = 家主辈分 + 1）。

**Independent Test**: 只实现买人口入口与成员初始化（不插入结算步）：连续购买同一年的第 1/2/3 名，
断言价格恰为 10 / 20 / 30 贯（§9.5 定价 **MUST NOT** 乘支出系数，Assumptions 24）、辈分 = 家主辈分 + 1、
年龄落在 8~16 含端点、无父母引用、姓名冠家族姓；跨年 1 月后再购买，价格回到 10 贯。

**Acceptance Scenarios**:

1. **Given** 本年度尚未购买过任何人且现金 + 储蓄 ≥ 10 贯，**When** 购买第 1 名，
   **Then** 扣 10 贯、落 1 条 `PersonPurchase` 条目与 1 条 `PersonBought` 事件类条目、
   新增 1 名在册成员且计入计口口径。
2. **Given** 本年度已购买 2 人，**When** 购买第 3 人，**Then** 价格恰为 30 贯（`10 × 3`）。
3. **Given** 现金 + 储蓄不足以支付当次价格，**When** 发起购买，**Then** 拒绝、随机消费 0、
   MUST NOT 转贷款、MUST NOT 记账 0 金额条目。
4. **Given** 跨过 1 月，**When** 购买本年第 1 名，**Then** 价格回到 10 贯。
5. **Given** 家主空缺（`HeadId == null`），**When** 发起购买，**Then** 拒绝
   （`BoughtCollateralGeneration` 无基准，见 Assumptions），随机消费 0。
6. **Given** 买来者入册，**When** 该成员首次与家族内成员成婚，**Then** 其辈分对齐配偶辈分，
   且这是它此生**最后一次**辈分变动（外来者总计变动两次，§4.4）。

### Edge Cases

- **同一月内多人死亡**：每个死亡者的归档与继任判定 MUST 按 `PersonId` 升序逐一进行；
  若家主与其唯一在世儿子同月死亡，则继任 MUST 落在「死亡集合处理完毕之后」的候选集上（不得选出已亡者）。
- **家主继任与买人口同月**：先继任后买人口，买来者辈分取**继任后**家主辈分 + 1。
- **新生儿与家主继任同月**：家主候选 **MUST NOT 设年龄下限**，新生儿与其他在册男性**同口径**参与 FR-036
  的四档判定（因其年龄最小，实际只会在 ①/② 档候选仅它一人、或它是家族内唯一在册男性时当选）；
  继任 MUST 落在死亡集合处理完毕后的候选集上（Assumptions 25）。
- **同一人跨子步被多次登记死亡**：`DeathRegister` MUST 只保留**首个**登记及其死因，优先级固定为
  **⑧-b 分娩 > ⑧-c 病亡 > ⑧-e 饥馑 > ⑧-f 寿终/夭折**；⑧-g 是当月**唯一**置 `Deceased` 的处所，
  且 MUST 按 `PersonId` 升序归档。
- **外嫁成员的天命寿数**：照常判定并归档，MUST NOT 使其回到在册/计口集合，MUST NOT 参与家主候选。
- **服刑成员**：照常接受患病、成长、体质与寿数判定（§4.1 只规定寿数不豁免）；
  但服刑者**不能**指派读书（既有 `Assignable` 口径），故会落入「16 岁以上未读书 −0.5/月」。
- **待阙成员**：与在册同口径（002 已定「待阙照常计入计口」）。
- **丧偶**：`SpouseId` 置空并追加 `FormerSpouseIds`（`Family.EndMarriage`），可再婚；
  再婚 MUST NOT 覆盖既往婚姻历史。
- **患病与饥馑叠加**：体质下降 MUST NOT 重复计算同一原因（同一月内患病与饥馑各按自己的量扣一次，
  不得相互替换）；救济期按 §5.4 字面不减体质（含患病）。
  **最坏情形（Q6 已记录、MUST NOT 由实现自行放宽）**：饥馑严重期无健康月 `+1` 恢复（§4.3 要求
  「生活费付清且非饥馑」）、疾病照按 `2 + 8s` 扣体质，故 `≥ 24` 岁且体质低于阈值的成员会加速下滑；
  §5.4 的每月 5% 死亡判定在同一人群上叠加。若实机手感显示「灾年连锁病亡」过强，
  调整 MUST 经规格书 §17 裁决（可动的是饥馑扣减时长或药费档位），MUST NOT 在实现里静默削弱。
- **确诊当月（宽限月）与寿终同月**：宽限月只豁免体质扣减、药费与清除判定，
  MUST NOT 豁免天命寿数（§4.1「患病不豁免」）或其他死亡来源。
- **疾病清除概率计算值 > 1**：疗程加成使 `min(1, (体质 × 1.10/100 + 0.20) × m_q + b) = 1` 时
  MUST 短路为必愈，且 MUST NOT 因此产生额外随机消费（保证确定性与同种子可复现）。
- **疾病程度为 1 且体质为 0 当月**：先按 `2 + 8s` 扣至 0、再判清除；体质为 0 即病亡（死亡优先于清除判定，
  否则会出现「已死之人痊愈」的中间态）。
- **未治疗的疾病**：MUST NOT 自行过期；只能在清除判定命中或体质归零时终结。
- **新生儿出生即被判定夭折**：出生在 ⑧-b、第一次夭折判定在**同一月的** ⑧-f，两者 MUST 分属不同子步
  （MUST NOT 在 ⑧-b 内既出生又夭折），且此后的判定落在满 1 岁、满 2 岁的生日月。
- **分娩与母亲死亡同月**：新生儿照常入册，母亲归档；若母亲是家主……家主为男性，此例不可能，
  但若母亲是某人在册配偶，则 `SpouseId` MUST 被置空。
- **年龄档切换的当月口径**：患病免病与三段年龄增益 MUST 按 `AgeAt` 的**整岁**口径判定（与既有
  `AgeBracketPolicy.IsAdult` 同口径）：成员在满 3 岁的**当月**起接受患病判定、满 12 / 24 岁的**当月**
  即切到下一档增益；MUST NOT 引入「生日当天」这类月内时刻细分。
- **捉婿提议与官员变动同月**：`P` MUST 取该次判定开始时（⑧-a 执行前）的在册官员快照——
  当月 ④ 官吏推进的任免已生效（④ 先于 ⑧），但当月**死亡 / 继任**造成的减少属其后子步，
  MUST NOT 回溯修改本次 `P`。
- **玩家拒绝捉婿提议**：MUST NOT 支付任何款项、MUST NOT 产生成员与婚姻关系、MUST NOT 落账本条目；
  提议立即失效，且该一甲成员「每科一次」的名额**已消耗**（MUST NOT 于次月重掷）。
- **无官员家族（`P = 0`）**：榜下捉婿 MUST 退化为 Q1 原口径（概率 `30% × 负面事件系数`、
  金额落 500~1000 贯、配偶功名为白身），MUST NOT 出现除零或负值。
- **官员压力极大**：`P` 无上限（多人十八级叠加），金额 MUST 按 `(1 + P)` 照常放大并四舍五入取整，
  概率 MUST 随 `(1 + P)` **单调下降但恒为正**（MUST NOT 被截断为 0 或负数）。
- **家族只剩外嫁成员**：MUST NOT 在本特性内判定绝嗣（§15 属 ⑧）。
- **托媒成功但对象年龄落在 ±5 之外**：MUST NOT 发生（对象年龄由成员年龄 ±5 派生）。
- **对象为「仕族」却本家无钱**：金额计算照常，支付失败即拒绝（不转贷款）。
- **同月多次买人口**：允许（§9.5 无上限），价格按「本年度已购数 + 1」递增，计数在同一月内即时更新。
- **确定性**：同一存档 + 同一动作序列 MUST 逐字段可复现；所有新随机消费 MUST 在结算次序表中登记。
